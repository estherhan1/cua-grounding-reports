From error patterns to finer tasks and metrics

What the agents in all our runs get wrong, and a proposal for the next version of the benchmark: sub-tasks that isolate each failure, and metrics that say where an episode went wrong instead of only pass/fail.

October 2026. Draws on the Holo4 + search report, the gpt-5-mini report and its failure breakdown, the gpt-5-mini rerun, the switching examples, and the earlier Qwen3-VL-8B runs. Numbers marked "new" were computed for this page from the saved Holo4 step logs.

Where we are. The benchmark has 455 desktop tasks. Each one needs a recent fact from the web and a change on the desktop (a spreadsheet, a document, an email draft, a JSON file). We ran three agents on it: Qwen3-VL-8B, gpt-5-mini and Holo4-35B. Every task is scored by one check at the end: solved or not.

The problem with one score. A failed episode can fail in very different places. The agent may never look the fact up, find the wrong fact, find the right fact and type it wrongly, or type it correctly and never save. One pass/fail number mixes all of these, and run-to-run noise is large. So two agents (or two versions of an agent) can get the same score for completely different reasons.

Latent task: the normal task. The agent has to find the fact itself.
Explicit task: the same task with the fact written into the instruction. It measures the desktop part alone.
Search tool: a web search service the agent can call. Without it, the agent must research in the browser.
"States the facts": the agent's own reasoning text contains every needed value. A lower bound on "found the facts".

1 · Error patterns we have seen

Grouped by where in the episode the failure happens. "Evidence" gives the number and the run it comes from.

A. Finding the fact

PatternWhat it looks likeEvidence
A1 Never looks it upThe agent writes a guess, a placeholder or last year's value without searching.gpt-5-mini: the main cause of 40% of failures without search, 15% with it. Qwen3-VL-8B almost never called the search tool unless forced: its trigger is "if you are not sure", and it is always sure.
A2 Thinks the event has not happened yet"The 2026 World Cup hasn't happened yet", then it searches for a prediction. Or it searches the wrong year ("US Open 2025").New: 21% of Holo4 episodes with the search tool and 36% without it contain such a statement. Every task here is about something that already happened.
A3 Accepts a near-miss factA prediction instead of the result. The author of a similar public post instead of ours. The tournament champion instead of the team that played the most games. Last year's table.Reddit World Cup (Messi, from a betting preview), Reddit personal-finance task ("kneechalice" from public reddit.com), Little League (an email suggests the champion, Curaçao; Holo4 did not fall for it), US Open (2025 list).
A4 Drops a conditionFinds the right kind of fact but ignores a filter in the ticket: "quarter-finals onward", "only weekends inside the window", "only bracket games".US Open (took the 4th-round match), Japan box office (one weekend instead of ten), many Calc and VS Code tickets.
A5 Stops at the summaryThe search result is a short summary without the table or number. The agent either guesses from it or switches to the browser.152 of 613 Holo4 search episodes switched from the search tool to the browser, mostly for this reason. 193 of 1,805 searches were requests to read a whole page.
A6 The source blocks itCloudflare check, CAPTCHA, "403 Forbidden", the site blocks the cloud address, or a site that never loads.7.0% of Holo4 episodes without the search tool vs 2.8% with it hit a wall; 1 of those 60 was solved. 29 tasks use sources the cloud machines cannot reach.
A7 Asks the same thing againThe same query repeated, or the same failed idea (search for our forum post on the open web) repeated.gpt-5-mini: 46% of searches repeat an earlier query (it only sees its last 3 steps). Reddit Nobel task: the same search 8 times. Holo4 repeats almost never.

B. Doing it on the desktop

PatternWhat it looks likeEvidence
B1 Corrupts the file while editingClicks to place a cursor and types, so text is inserted instead of replaced. Deletes a needed line. Leaves JSON that no longer parses.Qwen3-VL-8B: 0% on the VS Code JSON family even with the answer given, because every click landed in the same column. gpt-5-mini: editing errors rose from 11% to 23% of failures once search removed the research errors; 63 of 116 failures that had the right fact died here.
B2 Cannot reach the objectThe file icon is behind a maximised window, the right sheet tab or mailbox is never opened, dialogs loop (Import Options, Keep format, Tip of the Day).gpt-5-mini failure breakdown; Thunderbird opened a mailbox without the seeded mail until we fixed the profile.
B3 Skips a step it cannot checkInstructions say "switch to public transport", the agent never clicks the transit tab and moves on.Google Maps tasks: 4/12 with the answer given, 11/12 once the step said what the screen should show afterwards.
B4 Value right, format wrongA date typed into a General cell becomes a serial number; a reply saved to the wrong drafts folder; doubled quotes from auto-closing.Found by our task audits; fixed in the evaluators, but agents still produce these.

C. Managing the episode

PatternWhat it looks likeEvidence
C1 Says "done" when it is notThe agent stops and declares success without reading back what it wrote.New: when Holo4 with the search tool said "done", it was right 27% of the time (59% with the answer given). Half of all its failures end this way.
C2 Runs out of stepsLong research or editing loops reach the 50-step limit.New: 41% of Holo4 search episodes and 60% without search. On the harder v1 tasks, 149 of 297.
C3 Gets stuck repeating one actionThe same click or the same keystrokes 5 times or more in a row.New: 6.7% of Holo4 search episodes; 39 of those 41 failed. Earlier Qwen3-VL-8B: one line retyped 13 times. More steps make it worse, not better.
C4 Does not switch when it shouldKeeps using the channel that already failed, or switches only once.Of about 20 Holo4 switches that followed a stated failure, none was solved. Going from the screen back to the search tool happened in only 7 of 613 episodes.

2 · Finer sub-tasks

Each sub-task isolates one pattern. All of them can be generated from the tasks we already have, because every task already has its facts, their sources, the correct values and an automatic checker. Most are pairs: the same task in two versions that differ in one thing, so the score difference measures exactly that one pattern.

Sub-taskWhat changesMeasuresHow to build itCost
S1 Research onlyNo desktop work. The agent reads the same ticket (as text plus a screenshot) and answers with the fact values.A1 to A5 without any desktop noise. Score per fact.Reuse each task's instruction, seed text and fact list; check answers against the stored values.Low. No virtual machine needed.
S2 Desktop only, by sizeThe explicit task (already exists), plus versions that change 1, 3 or all fields.B1 per field: does the error rate grow with the number of edits?Split each explicit task's checker rules into one-field versions.Low.
S3 Find the cueStop after the agent has opened the ticket. Ask which facts it needs and for which items.Whether it read the ticket correctly, including its conditions (A4, B2).Gold = the task's fact list and filter rules, already in the task metadata.Low.
S4 Date-anchor pairsVersion 1 says "this year's"; version 2 states the date ("the 2026 final, played on 19 July 2026").A2: how much of the failure is the agent believing the event is in the future.Template rewrite of the instruction; same checker.Low.
S5 Near-miss trapsPlant a plausible wrong value where the agent will see it: a prediction note, last year's file, a similar post by another user, an email that suggests the wrong answer.A3. Because each trap has its own wrong value, the checker can label the failure automatically ("took the trap").Add one seeded file or message per task; record its value as a known wrong answer.Medium.
S6 Condition pairsThe same task with and without one filter ("quarter-finals onward", "inside the window").A4: the drop in score when a condition is added.Pick tasks where the filter changes the answer; recompute the gold without it.Medium.
S7 Blocked-source pairsThe official source is reachable in one version and blocked in the other (we control the network for the virtual machines).A6: can the agent find another route (search tool, mirror, other official page)?Block one domain per task in the network rules; same checker.Medium. Needs the network rule we decided not to build yet.
S8 Check and fixThe file already contains the agent-style answer, with one injected error (wrong value, broken JSON, inserted text). Task: check it against the source and fix it.C1 and B1: does the agent read back and verify?Take the gold file, inject one error from the B1 list; checker = gold.Low.
S9 Which channelThe fact is only on the desktop, only on the web, or the two disagree. Like the Reddit tasks, where only the forum had the post.C4: does the agent pick, and switch to, the right channel?Extend the Reddit design to the desktop: put a ticket code in a local file and a public fact on the web.Medium.

S1, S3, S4 and S8 need no new facts and no new evaluator code, so they could be built in a few days. S5 and S6 need hand checking that each trap or filter really changes the answer.

The pass/fail score stays the headline. These metrics are reported next to it, and most of them can be computed from the logs we already save.

Fact counts use the "states the facts" heuristic, which undercounts on the harder v1 tasks. For the "answer given" column the facts are in the instruction, so fact recall is trivially high there.

Two things the single score did not show. First, the search tool more than doubles fact recall, but only about a third of episodes that had every fact went on to a correct file. Second, the agent's "done" is unreliable in every setting, including when it was handed the answer. Both point to the desktop half (B1, C1) as the next bottleneck for Holo4, which the S2 and S8 sub-tasks would measure directly.

5 · Suggested order

  1. Re-score what we have (no new runs). Add the "available now" metrics to every report: fact recall, conversion, "done" precision, step-limit, loop and future-belief rates. About 1 day.
  2. Save the final files. Change the harness to copy the edited file and the checker's per-rule log out of the virtual machine before it is deleted. This unlocks field score, file integrity and saved. Small change, applies to all future runs.
  3. Build the cheap sub-tasks first: S1 research only, S4 date-anchor pairs, S8 check and fix, S3 find the cue. About 100 tasks each from the existing bank.
  4. Then the trap and condition pairs (S5, S6), which need hand checking, and S7 if we decide to add the network rule.
  5. Run two rounds per arm and report averages, so differences between agents are not noise.
