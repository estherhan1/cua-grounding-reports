456 題，latent 版本（無提示），gpt-5-mini 跑 OSWorld PromptAgent，觀測為 screenshot + a11y tree，上限 50 步。每題比較兩組：不給 search 與 給全功能 search（Serper，top-3 抓頁，可直接讀網址），兩組都用修好 bug 後的程式。

執行日期 2026-10-03/04。顯著性用 McNemar exact 檢定，以 task 配對。「fact 出現在搜尋結果」與「有打出 fact」是啟發式判斷：比對 fact 值正規化後的前 12 字元。

兩輪合併：search 的效果穩不穩？

只用兩輪之間沒有修改過的題目（修改過的題目兩輪不可比）。每題算兩輪合計解出幾次，給 search 減去不給 search；符號檢定看「哪一邊比較好」的題數，置換檢定在每題內隨機交換兩組標籤 20,000 次。

研究效率：search API vs VM 裡的瀏覽器

不給 search 的 agent 仍可在 VM 裡開 Chrome 查資料，所以這裡比的是兩種研究管道。資料為兩輪合計。「拿齊事實」＝ agent 自己的推理文字裡第一次寫出每個事實值的那一步（正規化後的前 12 字元比對，屬保守估計）。曲線為「到第 k 步時已拿齊全部事實的 episode 比例」。

找到了，但沒做完

給 search 組裡，各階段的 episode 數。多數 episode 搜到了正確的值，很多也打進了檔案，但最後通過 evaluator 的很少。瓶頸在 GUI 執行，不在研究。

修 bug 前後

修了兩個 bug。第一個：a11y 模式下，搜尋結果沒有放進當前這一輪的 user turn。第二個：```DONE ``` 被解析成空動作。另外，task 指令裡多加了一行 search 說明。修了之後搜尋次數變多，但兩組的解題率差距沒有顯著改變。
