Benchmark reproductions — published number matched

OSWorld — Qwen3-VL-8B-Instruct34.74%published 33.9 · reproduced369 examples
What it is
The full 369-task agentic computer-use benchmark, one card per episode: every model call with the frame it actually saw, its verbatim response, the parsed tool call and the pyautogui line that ran. 10,293 model calls in total.
Finding
Reproduces the published number (+0.84pp, z=+0.34, well inside the CI). The binding constraint was the SCAFFOLD, not sampling: OSWorld's stock PromptAgent scores 24.4% where the model-native Qwen3VLAgent scores 40.2% on the same 209 tasks (McNemar p=0.0000). 8 Google-Drive tasks cannot run at all.
Try this
Filter to ✗ Wrong and search “cap” for the 162 episodes that burned all 50 steps — the dominant failure mode is looping, not misclicking.
OSWorld-G — Qwen3-VL-8B-Instruct58.87%published 58.2 · reproduced564 examples
What it is
The single-step grounding benchmark, all 564 rows: screenshot with the ground-truth target and the model's predicted click drawn on it, plus the raw response. Covers the bbox (470), polygon (40) and refusal (54) subsets.
Finding
Reproduces the published number with 0 unparseable rows, so it is genuine grounding and not an output-format artifact. The refusal subset scores 0.0%: the model emits a confident click for every ungroundable instruction instead of abstaining.

Instruction refinement — Phase 1 (OSWorld)

OSWorld — Phase-1 refined instructions (no tools)28.48%−6.40pp vs original wording, McNemar p=0.0009369 examples
What it is
The same 369 tasks, same model, same native scaffold and settings as the 34.74% reproduction, with only the instruction text replaced by the Phase-1 refinements (OSWorld_refine1.xlsx). Config and evaluator verified byte-equal per task. Every card shows the original and refined wording side by side, the baseline reward and a FIXED / BROKE tag.
Finding
Refined wording costs 6.4pp paired on 361 tasks (fixed 10, broke 32). The loss is concentrated where the refinement hides the target behind a real-world clue: chrome −19.4pp, ‘Indirect entity relation’ −27pp (0 fixed / 10 broke), 2+ hops −7.8pp; one-hop rewordings move only −5.3pp. 67 late multi_apps/os episodes lost their screenshots to the disk guard; their text traces are intact.
Try this
Search “brk” and filter to ✗ Wrong to read the 32 tasks the rewording broke; most fail at the first step, before any UI difficulty.
OSWorld Phase-3 — five self-made tasks with evaluators0 / 54 solvedonly T3 scores at all (0.42 mean) · 115 episodes incl. four hybrid GUI+CLI arms66 examples
What it is
Five desktop tasks written to the shape of the Qwen-UI-Agent demos (real-world motive, several candidates, an entity named only by a clue) but each shipping an OSWorld-style config and evaluator, so unlike those demos they can be scored and re-run. Each exists in a clean and a decoy variant; same model, scaffold and budget as the 369-task runs.
Finding
The agent never consults a source it is pointed at: in T1 and T4 it answers from memory with the authoritative page open in an adjacent tab, so clean and decoy score identically — the decoys are never read either. Where it does pick the right evidence (T3: the newer mail in 6/6 episodes) it transcribes it badly or loses it to a paste-undo loop. Giving it a real shell tool changes the failure mode and not the outcome: on T5 it writes one pipeline, sees exit code 0 with no output, and terminates in two steps having produced 240 rows of commas — it never reads the file back.

Search “ARM” for the hybrid GUI+CLI episodes and read the shell commands against what the model was shown back; search “t3” to compare the four 0.633 episodes with the two that oscillated Ctrl+V / Ctrl+Z to the step cap.
OSWorld — Phase-2 initial-state changes (decoys + de-leaked tabs)26.03%−2.50pp vs Phase-1, p=0.078 · de-leaked tabs −33pp (n=9), decoys −0.3pp (n=219)369 examples
What it is
Same Phase-1 instructions; the initial state now carries a decoy input file beside every real one (221 tasks, 395 files) and the 9 indirect-entity Chrome tasks no longer start on the site the wording hides. Instruction and evaluator byte-identical to Phase 1. Each card lists its changes; the P2-D trajectory checks (decoy-touch, infeasible-task mutations) are in the intro.
Finding
Decoy files are a null (−0.3pp, 5 fixed / 6 broke): the agent opened a decoy in only 7 of 230 episodes. De-leaking the starting tab is the real lever: the 9 tasks fall from 44% to 11% (0 fixed / 3 broke). The 133 untouched tasks moved −4.0pp between two greedy runs, which sets the run-to-run noise floor for this benchmark at roughly ±4pp. Infeasible tasks: 38 mutating actions on average before stopping, never zero.

OSWorld — Phase-1 refined + search harness27.39%−1.11pp vs refined no-tools, p=0.48 (null) · 1 search in 361 episodes369 examples
What it is
The refined-instruction run repeated with the search-GUI harness ported into the native Qwen3VLAgent as a second tool (`search`: live Serper + page fetch, ≤5 lookups, each consumes a step, plus an explicit search-first hint in the task text). Every card shows the intercepted query and the text the agent was handed.
Finding
The agent does not switch channel: 1 lookup in 361 episodes (~10k decision points), and that one was a misfire (web-searching a local .docx). Score is indistinguishable from the no-tool refined run (fixed 7 / broke 11). A step-1 probe with the real model found the same: 1/56 across four prompt variants, positive controls included. The harness is confirmed enabled in every episode’s runtime log.

Visual instruction refinement — 5 arms53.07%+3.5pp, p<0.0011581 examples
What it is
Five grounding arms over the full benchmark. The arm under test lets the instruction-rewriter see a 2.5× zoomed crop of the target before it writes its description; the grounder then works from the original instruction plus that description.
Finding
Letting the rewriter SEE the target beats letting it only read the instruction. 132 examples fixed, 77 broken.

Recorded dead ends — kept because the negative result is the finding

Serper-only agentic refinement−2.02ppnet −32, p=0.0111581 examples
What it is
The agent may call Text_Search, Image_Search and Webpage_Visit, and must call at least one before it is allowed to rewrite the instruction. Full benchmark.
Finding
Search makes grounding worse, and significantly so. Retrieved facts about an app's UI are usually things the model already knew; when they are wrong, a confident retrieved claim overrides correct on-screen perception.
