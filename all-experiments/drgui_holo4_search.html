Does a search tool help an AI finish computer tasks?

What this report is about

We ask an AI to finish a piece of work on a computer with the mouse and keyboard, and we deliberately make the work depend on facts it can only get from the web. The question: if we add a search function to its list of tools, does it finish the work more often?

The model tested is Holo4-35B-A3B. It sees only screenshots and gets at most 50 steps per task. The two settings differ in one thing: whether the model has a tool that searches and reads web pages directly. Without the tool it can still open a browser and look things up itself. Almost all the facts the tasks need were published after July 2026, so the model could not have seen them in training.

Terms used

With / without the search tool: whether the tool list includes search.
Answer given: the instruction already states the facts, so only the computer work is tested.
Run: one attempt at a task, from the start until the model stops.
Had all the facts: the first point at which the model's own reasoning text states every value the task needs.
Rewritten tasks: tasks from OSWorld, a public computer-use test, rewritten so that they need facts from the web. Some need one fact (85 tasks) and some need several (55 tasks).
New tasks: tasks we designed from scratch. Batch 1 has 18 tasks. Batch 2 has 297 and is harder, with 7.5 facts per task on average.
Core set: the rewritten tasks plus batch 1 of the new tasks, 158 in all. These were run in every setting.
Completed: the automatic checker confirmed that the result is fully correct.

      3. Results

      Setup and method

      The runs took place from 9 to 11 October 2026. Holo4-35B-A3B is an open-weight model released by H Company under the Apache 2.0 licence. We used the 8-bit floating-point (FP8) version, served on one A6000 graphics card. The agent setup follows the official documentation: the model sees screenshots only and not the on-screen text structure, it outputs actions as tool calls, coordinates run from 0 to 1000, the last 3 screenshots are kept, each task gets at most 50 steps, and the sampling temperature is 0.8. The search tool uses a Google search service, the same pipeline as in the earlier gpt-5-mini experiments.

      Completion rate by task group

      Each task was run twice with the search tool and twice without, so those denominators are twice the number of tasks. "Answer given" was run once, so its denominator is the number of tasks. Each bar shows the percentage first and the count in brackets.

      Statistical tests and run details

      The tests compare the two settings task by task. The smaller the number, the less the gap looks like chance; below 0.05 is usually read as clear evidence of a difference. The exact paired test (McNemar exact test) is used for a single run. The sign test and the permutation test are used for the two runs combined; the permutation test uses 20,000 resamples.

      New tasks, batch 2: 297 tasks, one run each

      This batch is harder, with 7.5 facts per task on average. By software it splits into file manager, Thunderbird mail and Writer documents, Calc spreadsheets, and VS Code, plus a small group of 3 more file-manager tasks. Each task was run once with the search tool and once without, so each bar's denominator is the number of tasks in that software group. This batch has no "answer given" runs, so we cannot estimate the ceiling for the computer work alone, and with a single run we cannot measure run-to-run stability. The gpt-5-mini numbers come from one run on the corrected tasks.

      Steps and searches

      These tasks often need 5 or more values, and the "had all the facts" measure clearly undercounts here: some completed runs wrote the values straight into the file without restating them in the reasoning text. Treat the share of runs "without all the facts" as an upper bound. Because this batch has no "answer given" runs, failures after the facts were found cannot be split further into computer-work problems and other causes.

      Speed of finding the facts: search tool versus opening a browser

      "Had all the facts" is the step at which the model's own reasoning text first states every value the task needs, matched on the first 12 characters after normalising. Only core-set tasks with checkable values are counted, with both runs combined. Each bar's denominator is the number of checkable runs, with the count in brackets. For some tasks the list of candidates is already in a file on the virtual machine, and reading that list out also counts as stating the value, so this measure is slightly too high for both settings.

      Failing even with the search tool: where it goes wrong

      This covers the 158-task core set. Every run with the search tool is put into one of four groups. "Had the facts, but fails even with the answer given" points to a computer-work problem. "Had the facts, and succeeds with the answer given" means both the facts and the ability were there, yet this run still failed, through reasoning, applying the task's rules, or run-to-run chance. Each bar's denominator is the total number of these runs.
